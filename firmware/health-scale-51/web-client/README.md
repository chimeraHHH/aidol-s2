# 小咪 · 蓝牙串口实验台

参考供应方蓝牙串口调试工具，独立实现经典蓝牙串口网页，并接入健康秤文本协议。供应方 APK、原始实物接收记录和部署账户配置不包含在本目录。

## 开始测试

本机在仓库根目录执行以下命令，无需安装前端依赖：

```sh
cd firmware/health-scale-51/web-client
python3 serve.py --port 18765
```

在当前电脑的 **Chrome** 打开 `http://127.0.0.1:18765`。服务仅监听本机回环地址。已有的 [HTTPS 测试入口](https://aidol-scale-lab.cnhuayiming.chatgpt.site/) 使用相同网页源码，需要站点所有者的访问权限。

1. 给 JDY-31 供电，在当前设备系统蓝牙中配对 `JDY-31-SPP`，供应方默认配对码 `1234`。
2. **本次 macOS 实测成功的路径：** 选择「真实设备」→「USB / 系统串口」→ 9600 → GBK，点击「选择并连接设备」，选择 **`cu.JDY-31-SPP`**。虽然菜单名称包含 USB，这里实际使用的是系统映射的蓝牙串口。先关闭其他占用模块的 APP。
3. 观察 RX 字节数、接收时间和重量曲线持续增长。连接后不自动发送命令；需要时可手动点击「连接测试」发送 `*%#`，或按实际固件版本选择 BMI 命令。本次实物验证只确认了被动接收，没有验证命令应答。
4. 没有模块时，选择「演示测试」并启动，或导入 `.txt` / `.bin` / `.hex` 原始报文回放。模拟与回放都有醒目标识，切回真实设备会清空模拟指标。

安卓 Chrome **138 及以上**已支持通过 RFCOMM 访问经典蓝牙串口；这里用 Web Serial，不会把 JDY-31 误当 BLE。仍以页面实际能力检测和设备选择结果为准。手机访问电脑的普通 HTTP 局域网地址不属于安全上下文，不能据此测试手机蓝牙；使用 HTTPS 入口，或让服务运行在手机自己的 localhost。电脑侧的旧版 Chrome、Safari、部分内嵌浏览器可能没有所需接口，或被外层页面的权限策略限制。

## macOS 连接排查与已验证路径

2026-10-17 的设备测试中，Mac 已配对 JDY-31-SPP，原生工具成功打开 SPP 的 RFCOMM 通道并收到 720 字节。Chrome 的「JDY-31 经典蓝牙」路径仍在 `chrome://device-log/` 报 `SDP query timeout`。

切换为「USB / 系统串口」，选择已生成的 **`cu.JDY-31-SPP`** 后，原来的 HTTPS 页面成功连接。页面在真实设备模式下，样本从 13 增至 26，RX 从 1170 增至 2340 字节；随后截图记录了 31 个样本。TX 始终为 0。汇总见 [实测记录](../validation/web-live-20261017.json)。

如果选择器同时列出 `JDY-31-SPP - Paired` 和 `cu.JDY-31-SPP`，本机已验证的是后者。其他电脑可先尝试经典蓝牙路径；出现相同 SDP 超时时再选择系统映射串口。如果系统中尚无映射串口，先完成系统配对；本项目的 [macOS 原生工具](../README.md#macos-原生接收工具) 也可用于诊断。使用原生工具后关闭其窗口，释放连接，再连接网页。

这次实测确认了传输和页面实时解析。身高为零、设备 BMI 为异常负值的报文原样展示，称重精度、标定和传感器状态仍需单独验证。未烧写或校准开发板。

## 已实现

- 经典蓝牙 SPP / USB 或系统串口选择、9600–115200、数据位/停止位/校验设置、连接与断开。
- GBK / UTF-8 流式解码，支持汉字跨接收分块；文本 / HEX 视图及字节计数。
- 原板 `*%#`、`*BMI#`，修复版 `*%`、`*BM0#`，手动 ASCII / HEX 发送及可选换行。命令不会自动发送；不切换 DTR/RTS，不烧写、复位或校准开发板。
- 解析原始体重、距离/身高和设备 BMI。负值、异常长值不被偷偷修正，不在前端加 5kg 清零门槛，不使用人体 BMI 判定猫咪健康。
- 当前会话最近 120 个重量样本；暂停终端显示不暂停接收。日志最多保留 2000 条，界面最多展示最近 350 条；达到上限会提示。JSONL 导出包含原始 HEX、接收块文本、时间、来源和会话号。
- 明确标注的模拟测试、1MB 内的本地原始报文回放。日志和接收数据仅保存在当前页面内存，刷新会清空；用户主动导出后才生成本地文件。

## 文件与验证

- `dist/`：可独立静态托管的网页，无第三方脚本、遥测、数据库或账号资料收集。
- `dist/protocol.js`：完整行解析、增量解码、ASCII / HEX 编码和模拟命令状态机。
- `dist/serial.js`：基于 Web Streams 的连接、读写锁及断开处理。
- `tests/`：使用 Node 内置测试器，运行 `npm test`。覆盖 GBK 每种分割位置、零/轻载/负值、分包命令、HEX 验证、被动连接、拔出清理及取消连接。
- `reports/`：被忽略的本地测试和截图目录；公开的验证汇总在上级 `validation/`。

演示用 3.1–3.4kg、1.70m 等固定输入测试协议，不是实物数据；演示 BMI 按本地固件整数公式生成。演示状态机只回应修复源码实际支持的命令，因此原板 `*BMI#` 在演示里不会收到杜撰的成功回应。

模拟/回放验证与实物接收分开记录。当前已验证 macOS 系统映射串口到 Chrome 的实物接收；其他操作系统、安卓实体机和称重精度尚未因此获得验证。本模块不改动单片机固件或安卓项目。

浏览器依据：[经典蓝牙 RFCOMM / SPP](https://developer.chrome.com/blog/serial-over-bluetooth)、[Web Serial 读写与关闭](https://developer.chrome.com/docs/capabilities/serial)、[Chrome 138 安卓支持](https://developer.chrome.com/release-notes/138#web_serial_over_bluetooth_on_android)。
